# rkllm-rs

Rust bindings to `librkllmrt`, the Rockchip RKLLM runtime for NPU-equipped
SoCs such as the RK3588.

| Crate | What it is |
| --- | --- |
| [`rkllm-sys`](crates/rkllm-sys) | Raw FFI bindings, generated by bindgen and checked in. |
| [`rkllm`](crates/rkllm) | Safe wrapper over those bindings. |

## Requirements

- A Rockchip SoC with an NPU, and its kernel driver.
- `librkllmrt.so` version 1.3.0 or newer. It is not distributed here. Take it
  from [airockchip/rknn-llm](https://github.com/airockchip/rknn-llm) at
  `rkllm-runtime/Linux/librkllm_api/<arch>/librkllmrt.so`.
- A model in `.rkllm` format, produced by the RKLLM toolkit.

Building needs none of the above. The default feature loads the runtime with
`dlopen` at startup, so the crate compiles on any host. Only running needs the
hardware.

## Status

Version 0.1.0. The API is unstable.

Wrapped: model loading, text generation with a callback or a `Stream`, prompt,
token and embedding inputs, chat templates, function-calling configuration,
LoRA adapters, prompt caches, key-value cache control, and per-run sampling
overrides.

Not wrapped: multimodal input, cross-attention parameters, and the tokenizer
and embedding callbacks. All three remain reachable through `rkllm-sys`.

## Getting started

Neither crate is published yet, so depend on the repository:

```toml
[dependencies]
rkllm = { git = "https://github.com/boundarybitlabs/rkllm-rs" }
```

```rust
use rkllm::{Control, InferParams, Input, Param, RkllmSession, find_library_path};

let library = find_library_path()
    .next()
    .ok_or("no librkllmrt.so found")?;

let param = Param::new("/path/to/model.rkllm")?.max_new_tokens(256);
let session = RkllmSession::new_with_library(library, &param)?;

let mut input = Input::prompt("Why is the sky blue?")?;
session.run_llm(&mut input, &InferParams::new(), |output| {
    print!("{}", output.text().unwrap_or(""));
    Control::Continue
})?;
```

`RkllmSession` is `Send` and `Sync`. An internal lock serializes runs. `abort`
and `is_running` skip that lock so they can be called from another thread while
a run is in flight.

### Streaming

With the `tokio` feature, `run_llm_async` moves the run onto a blocking thread
and returns a `Stream` of owned chunks. Dropping the stream cancels the run at
the next chunk rather than at the end of the token budget.

### Examples

Both examples need a board and a model.

```sh
cargo run --release --example chat -- model.rkllm "Why is the sky blue?"
cargo run --release --features tokio --example stream -- model.rkllm "Why is the sky blue?"
```

They find the runtime through `find_library_path`, which reads `RKLLM_LIB` and
`RKLLM_LIB_DIR` before falling back to the usual system directories. Pass
`--library` to override it.

## Features

| Feature | Default | Effect |
| --- | --- | --- |
| `libloading` | yes | Resolve the RKLLM symbols with `dlopen` at run time. |
| `link` | no | Resolve them at link time. Needs `librkllmrt` present when building; set `RKLLM_LIB_DIR` if it is not on the default search path. |
| `tokio` | no | Adds `run_llm_async` and the `Stream` it returns. |

Under `libloading` the session is built with `RkllmSession::new_with_library`.
Under `link` it is built with `RkllmSession::new`.

## Versions

Two version questions travel separately, and they have different answers.

**Model artifacts are forward compatible.** A `.rkllm` converted with an older
toolkit runs on a newer runtime.

**The C API is not.** The checked-in bindings come from the 1.3.0 header. Used
against a runtime older than 1.3.0 they are memory corruption, not degraded
behaviour, because `rkllm_init` changed shape in that release. Check what you
have with:

```sh
strings /usr/lib/librkllmrt.so | grep 'RKLLM SDK'
```

## Verified configuration

Exercised end to end on this combination:

| | |
| --- | --- |
| Board | Orange Pi 5 Max, RK3588 |
| OS | Armbian, Debian trixie, aarch64 |
| Runtime | RKLLM SDK 1.3.0 |
| NPU driver | 0.9.8 |
| Model | MiniCPM4-0.5B, `w8a8_g128`, converted with toolkit 1.2.1 |

Generation ran at roughly 24.5 tokens per second with 633 MB resident. Other
Rockchip platforms are untested here.

## Regenerating the bindings

The bindings are checked in. The header is not vendored: the script fetches it,
generates, and records the source URL and the header's SHA-256 in each
generated file.

```sh
cd crates/rkllm-sys
./regen-bindings.sh                                 # upstream main
RKLLM_HEADER_REF=release-v1.3.0 ./regen-bindings.sh # a tag or commit
RKLLM_HEADER=/path/to/rkllm.h ./regen-bindings.sh   # a local copy
```

Needs `bindgen-cli`, libclang and curl.
